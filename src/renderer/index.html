          How a run works

          Four ideas, and you have the whole model
          01
          A node is an agent
          Each step spawns one agent CLI with its own model and prompt. Mix them freely: a cheap model triages, an expensive one writes, a third reviews.
          02
          An edge carries the decision
          One outgoing edge runs straight through. Several, and the step that just ran names the path on a final ROUTE: line, or you pin the edge to a text or regex match instead.
          03
          State is what you pass on
          Every node chooses how much of the previous output it inherits: all of it, the last fifty lines, or nothing at all when a step should start clean.
          04
          The run plays on the graph
          Nodes light up as they execute and the taken path stays drawn. Click any step to open its terminal, live or long after it finished.

          Hand the agent a goal and walk away. Husk snapshots the workspace, audits every event in a hash-chained log, and caps the run. When it stops, you can review the diff and revert with one click.
          
          
          
            
            
            
          Plain text. The model sees this as the first message.
          
          
          
          
          
            
          
              
              
            
          
            
          
              
              
            
          
            
          
              
              
            
          
            
          
              
              
          
                
                
              
          
            
          
          
          
          
          
            All caps are optional. Leave a field as is for the default, or enter 0 for unlimited.
            
          
          
          
          Team: an orchestrator splits the goal into non-overlapping slices, decides the team size, runs the agents in parallel, then a final integrator merges their work into one reviewable result. Caps apply to each team member separately.
          
          
          
          
            With a snapshot, Husk produces a diff against the pre-run state on halt or end and revert is one click. Without it, the agent still runs under the audit log and caps, but review and revert are unavailable (use git). Encryption (when the OS keychain is available) wraps every blob the audit log and snapshot store write.
